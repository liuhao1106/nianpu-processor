# 年譜整理工具 / Nianpu Processor

一鍵處理原始古籍刻本 OCR 後的中國年譜文本、或從識典古籍等下載的年譜文本，自動按年份切分、補全年號、整理段落。支援明清兩代及南明年號，具備自我進化能力。

本工具旨在為中國歷史人物、思想史、學術史研究搭建數位基礎文本——將結構混亂的年譜原始文本轉化為結構清晰、可由 AI Agent 自動識讀的 Markdown 格式，便於後續搭建 RAG 知識庫、進行大規模文本分析與史學研究。

## 功能

- **年份標題化** — 將 `八年己巳，先生年五十二` 轉為 `### 八年己巳，先生年五十二`
- **年號補全** — 自動追蹤當前年號，對無年號的條目標題補上年號
- **OCR 容錯** — 自動修正常見 OCR 錯誤（`先元年`→`先生年`、`十年九歲`→`十九歲` 等）
- **年號字形正規化** — `光緖`→`光緒`、`萬厯`→`萬曆`、`永厯`→`永曆`
- **月份/季節分段** — 每一年內按 `春/夏/秋/冬` 拆分，以 `**春正月**` 標記
- **嵌入式年份拆分** — 合併後段落中二次掃描隱藏的密集年份（如 `八年戊子五歲。九年己丑六歲`）
- **跨年邊界檢測** — 合併斷行時檢測年份邊界，防止不同年份誤合
- **自我進化 v3** — 每次處理後自動發現新年號、新字形、新前綴，含置信度評分和假陽性過濾
- **從修正中學習** — 手動修正後的結果會反饋到學習系統，自動標記無效學習
- **審查清理** — `--prune` 命令批量移除已被標記為無效的學習
- **檢查報告** — 處理完成後自動比對原始文本，報告遺漏年份、年齡空缺、年號切換

## 支援的年份格式

| 格式 | 範例 | 年譜 |
|------|------|------|
| 先生年N嵗 | `八年己巳，先生年五十二` | 方柏堂先生譜系略 |
| 直接年齡 | `十九年甲戌七嵗` | 萬清軒先生年譜 |
| 年N嵗 | `二十三年癸卯，年二十六` | 方柏堂變體 |
| 公年N歲 | `十八年辛丑，公年十有一` | 張清恪公年譜 |
| 跨行年份+年齡 | `康熙十六年\n公七歲` | 沈端恪公年譜 |
| 出生條目 | `仁宗睿皇帝嘉慶十三年戊辰八月二十四日先生生` | 通用 |
| 出生日期（無生字） | `明萬厯四十六年戊午十一月二十一日辰時` | 施愚山先生年譜 |
| 前綴+年號 | `大淸順治元年，先生二十六歲` | 明清之際年譜 |
| 明代年號 | `明萬厯四十七年己未，先生一歲` | 明代年譜 |
| 年月日前綴+生於 | `康熙十一年壬子，是年九月初九日辰時，生於京師` | 澄懷主人自訂年譜 |
| 無稱謂直接附年齡 | `十二年癸丑二歲` / `十年，壬子六十一歲` | 澄懷主人自訂年譜 |

## 處理流程

```
讀取檔案
  → 年號字形正規化（光緖→光緒）
  → OCR 錯誤修正（先元年→先生年）
  → 合併跨行年份+年齡（沈端恪格式支援）
  → 查找年份標記（前綴 + N年干支 + 先生N歲 / 直接N歲 / 澄懷主人無稱謂格式）
  → 插入 ### 標題
  → 追蹤並補全年號
  → 合併斷行（含跨年邊界檢測）
  → 嵌入式年份二次掃描（密集年份拆分）
  → 按月份/季節分段（**春正月**）
  → 輸出
  → 自動檢查報告
  → 自我進化學習
```

## 演算法說明

### 年份匹配

腳本使用多層正則匹配，按優先級依次嘗試：

1. **`birth`** — 出生條目：`[前綴]N年[干支]...先生生`
2. **`entry_sb`** — 有干支的年份（附稱謂）：`[前綴]N年干支 + [最多120字] + 先生N歲`
3. **`entry_no_sb`** — 無干支但年號明確：`[前綴]年號N年...先生N歲`
4. **`birth_no_person`** — 無稱謂出生條目（澄懷主人風格）：`康熙十一年壬子，是年...生於京師`
5. **`entry_sb_no_person`** — 無稱謂直接附年齡（澄懷主人風格）：`十二年癸丑二歲` / `十年，壬子六十一歲`

中間文字長度限制在 120 字（v2 從 60 字放寬），適應長註文年譜。合併斷行後另有嵌入式年份二次掃描，捕捉密集年份。

### 年號補全

處理器追蹤最近一次的年號。當遇到 `二年乙酉，先生二十七歲` 這樣無年號的條目時，會自動補上當前年號變為 `順治二年乙酉，先生二十七歲`。

### 自我進化 v3

每次處理完成後，系統會自動分析文本發現：
- **新年號** — 文本中出現但不在已知列表的年號（如「洪武」「永樂」），含置信度評分（< 0.4 不自動應用）
- **新前綴** — 「X皇帝+X年號」的新組合（含標點片段被自動過濾）
- **字形變體** — 年齡後綴的罕見字形（非單字或形近字被自動過濾）

發現的知識存入 `learnings.json`，同一年號出現 ≥2 次且置信度 ≥0.4 後自動應用到後續處理。

**v3 新增：**
- **置信度評分**：新年號自動計算置信度（0.0~1.0），含頻率、字元品質、上下文等多維評分
- **假陽性過濾**：純數字年號（如「一十」「二十」）、含標點前綴（如「過人遠矣。宣宗成皇帝」）、多字符字形（如「王歲」）在發現階段即被拒絕
- **從修正中學習**：透過 `_record_correction()` 記錄手動修正，自動標記對應學習為無效
- **審查清理**：`python nianpu_processor.py --prune` 批量移除已被標記為無效的學習
- **去重**：同一檔案重複處理時更新而非追加記錄

## 常見問題

**Q: 輸出亂碼？**

A: 確認輸入文件為 UTF-8 編碼。若非 UTF-8，腳本會自動嘗試 GBK/Big5。

**Q: 年份未被切分？**

A: 可能原因：
- 年份與年齡相隔超過 120 字（中間有超長註文）
- 缺少干支且無年號前綴
- 使用的年號不在支援列表中（自我進化系統可自動發現）
- OCR 錯誤導致年份模式無法匹配（如「先元年」→工具已內建修正）

**Q: 某個年份被誤切？**

A: 註文中的年份+年齡組合（如「按武夷先生卒於丁亥，年七十八」）因不含干支且「年七十八」格式不匹配 `先生N歲`，一般不會誤切。若仍有誤匹配，可調整 `entry_sb` 的 120 字限制。

**Q: 光緖和光緒有什麼區別？**

A: 兩者是同一年號的不同字形（緖=緒的異體），工具會自動將 `光緖` 正規化為 `光緒`。
