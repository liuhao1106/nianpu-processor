# 年譜整理工具 / nianpu-processor

一鍵處理原始古籍刻本 OCR 後的中國年譜文本、或從識典古籍等下載的年譜文本，自動按年份切分、補全年號、整理段落。支援明清兩代及南明年號，並已擴展至公元年號/民國紀年的近現代年譜（民國以後），具備自我進化能力。

本工具旨在為中國歷史人物、思想史、哲學史、學術史研究搭建數字基礎文本——將結構混亂的年譜原始文本轉化為結構清晰、可由 AI Agent 自動識讀的 Markdown 格式，便於後續搭建 RAG 知識庫、進行大規模文本分析與哲學史、思想史、史學研究。

## 功能

**切分與整理**
- **年份標題化** — `八年己巳，先生年五十二` → `### 八年己巳，先生年五十二`
- **年號補全與公元年標註** — 自動補上當前年號；標題干支後自動標 `（YYYY年）`
- **月份/季節分段** — 每年內按 `春/夏/秋/冬` 拆分，以 `**春正月**` 標記
- **嵌入式年份拆分** — 合併段落中二次掃描密集年份（`八年戊子五歲。九年己丑六歲`）
- **標點／斷句（LLM 驅動）** — 已整理但無標點的正文，由 LLM 依 `docs/標點規則.md` 分塊加標點（`nianpu_biaodian.py --chunk` → LLM 逐塊 → `--merge` → `--verify` 字符保全校驗）
- **歸檔／整理本同步** — 定稿後複製到 `年譜整理本/<書名>.md` 並同步 `_清單.md`／`_清單.tsv`（`nianpu_archive.py`）

**格式彈性**
- 七大格式族自動預分類：有稱謂／無稱謂直接年齡／無年齡純年份／公元年號・民國／行首裸干支／現代學者整理本（已有標題），詳見「支援的年份格式」表

**容錯與品質**
- **OCR 容錯與字形正規化** — 自動修正常見誤讀（`先元年→先生年`）、統一異體年號（`光緖→光緒`）
- **檢查報告** — 處理後比對原文，報告遺漏年份、年齡空缺、年號切換
- **三錨點一致性檢查＋CBDB 核驗** — 年號年／干支／年齡交叉驗證；`--cbdb` 以生卒年為錨、`--fix` 自動修正年號誤配（CBDB 缺席時以內部「干支+年齡」共識出生年回退，拔外部依賴）

**自我進化**
- 自動發現新年號／字形／前綴（含置信度與假陽性過濾）；`--record` 錄入手動修正（干支形近字累積 OCR 候選規則，`--status` 檢視、人工複核後手動升級 `_OCR_FIXES`）；`--prune` 清理無效記錄

**工具腳本**
- **RAG 對比** — `tools/nianpu_rag_compare.py` 量化「整理前 vs 整理後」檢索效果
- **語義槽位模型** — `--slots` 以 LLM 推得的槽位 JSON 驅動新格式，不需改正則
- **L2 衝突仲裁** — `nianpu_arbitrate.py` 把三錨點打架的標題＋上下文收集成仲裁請求，LLM 判定後保守套用（只動年號年序）並復驗
- **標點助手** — `nianpu_biaodian.py` 分塊／合併／字符保全校驗（標點本身由 LLM 執行）
- **歸檔助手** — `nianpu_archive.py` 複製定稿到整理本＋更新 `_清單.md`／`_清單.tsv`
- **回歸測試** — `tools/regression.py` 改動腳本後驗證歷史成績不退化：`testdata/` 九對「源＋黃金輸出」、`--selfcheck` 由黃金輸出實測基線、`--run` 出 PASS/FAIL 表＋自動生成 changelog 回歸行、`--full` 掃 E: 全庫、`--update` 刷新基線（詳見 [docs/回歸測試.md](docs/回歸測試.md)）
- **數據提取（延伸）** — 定稿 `.md` 交由 **[nianpu-social-network](../nianpu-social-network/SKILL.md)**（hyperextract）按年抽出人際／社交網絡，生成統一 persons／relations TSV（見[年譜擴展利用](#年譜擴展利用人際網絡數據提取)）

## 快速開始

本工具設計為**可供各種 AI 智能體（Claude Code、Cursor、Copilot 等）直接用自然語言調用**——智能體讀取本文件與 `SKILL.md` 後，會自動解析意圖並執行底層 `nianpu_processor.py`，無需手動拼寫參數。例如：

> 「整理這個年譜文件」→ 自動切分年份標題、補全年號、標註公元年
> 「把《黃黎洲先生年譜》整理好」→ 指定檔案處理
> 「核驗傳主生卒年並修正年號誤標」→ 觸發 `--cbdb`／`--fix`
> 「檢查已整理檔的可疑標題」→ 觸發 `--check`
> 「給已整理的年譜加標點」→ 觸發 `nianpu_biaodian.py --chunk` → LLM 逐塊標點 → `--merge`
> 「整理好後歸檔到年譜整理本」→ 觸發 `nianpu_archive.py <定稿.md> --book <書名> --note <備註>`

亦可在終端直接執行腳本：

```bash
# 處理年譜文件，輸出為「原檔名_已整理.md」
python nianpu_processor.py 涇舟老人洪琴西先生年譜_完整.md

# 指定輸出檔名
python nianpu_processor.py input.md output.md

# 語義槽位配置（v1 原型）：LLM 依新年譜開頭推得槽位 JSON，直接套用，不需改正則
python nianpu_processor.py input.md output.md --slots slots.json

# 一鍵套用年號誤配修正（不需 --cbdb；CBDB 缺席時以內部「干支+年齡」共識出生年回退）
python nianpu_processor.py input.md output.md --fix

# 錄入手動修正；干支形近字（單字替換）累積為 OCR 候選規則（--status 可檢視）
python nianpu_processor.py --record "順治乙亥" "順治己亥" 陳紫峰先生年譜

# 查看自我進化學習狀態
python nianpu_processor.py --status

# 清理已標記為無效的學習
python nianpu_processor.py --prune

# —— 標點／斷句（LLM 驅動，先切分、後逐塊標點、再合併校驗）——
python nianpu_biaodian.py --chunk 袁观澜先生年谱_合并_已整理_merged.md   # 按年份塊切分 → pun_01.md…
#   → LLM 依 docs/標點規則.md 逐塊加標點（直接編輯 pun_XX.md）
python nianpu_biaodian.py --merge 袁观澜先生年谱_合并_已整理_merged.md  # 合併 → 定稿.md（自動 verify）
python nianpu_biaodian.py --verify 袁观澜先生年谱_合并_已整理_merged.md 定稿.md  # 重跑字符保全校驗

# —— L2 三錨點衝突仲裁（LLM 判定，標題打架且 --fix 無法判定時）——
python nianpu_arbitrate.py --request 陳紫峰先生年譜_已整理.md   # 收集衝突＋上下文 → <名>_仲裁請求.md
#   → LLM 讀請求逐條判定（每行：{標題} → {修正後標題} 或 → 不改）
python nianpu_arbitrate.py --apply 陳紫峰先生年譜_已整理.md 仲裁結果.md  # 保守套用＋復驗

# —— 歸檔／整理本同步（定稿後最後一步）——
python nianpu_archive.py 袁观澜先生年谱_合并_定稿.md --book 袁观澜先生年谱 --date 2026-08-10 --note "全文標點整理"

# —— 回歸測試（改動腳本後必跑；詳見 docs/回歸測試.md）——
python tools/regression.py --selfcheck      # 從黃金輸出實測基線
python tools/regression.py --run            # 重跑 testdata 九案例 vs 基線 → PASS/FAIL 表＋回歸行
python tools/regression.py --run --full     # 另掃 E: 識典數據 全庫
python tools/regression.py --run --update   # 人工審核後以本次結果刷新基線
python tools/regression.py --smoke          # 快速冒煙
```

## 支援的年份格式

各格式按處理族歸類（對應「演算法」一節的 L1 格式預分類）。出生條目在各格式族下均啟用，用於年號播種。

| 格式 | 範例 | 年譜 |
|------|------|------|
| **1. 有稱謂（先生／公／府君／傳主名＋N嵗）** | | |
| 先生年N嵗 | `八年己巳，先生年五十二` | 方柏堂先生譜系略 |
| 先生N歲（〔〕年齡註解） | `十七年辛丑，〔是年先生五歲。〕始入小學` → 短註解展開為錨點：`### 成化十七年辛丑（1481年），先生五歲`（長註文如諱琛傳記保留） | 陳紫峰先生年譜 |
| 公年N歲 | `十八年辛丑，公年十有一` | 張清恪公年譜 |
| 公N歲＋雙欄合併殘留（預處理） | `五年丙午公二歲六年` → 移「六年」至其干支前：`五年丙午，公二歲。六年丁未，公三歲` | 朱文端公年譜（表格兩欄合併，殘留年份=下一年欄頭） |
| 跨行年份+年齡 | `康熙十六年\n公七歲` | 沈端恪公年譜 |
| 跨行拆分年份 | `康熙\n五年\n丙午` → 康熙五年丙午（年號/N年/干支拆三行） | 焦南浦先生年譜 |
| 前綴+年號 | `大淸順治元年，先生二十六歲` | 明清之際年譜 |
| 明代年號 | `明萬厯四十七年己未，先生一歲` | 明代年譜 |
| 傳主名前綴（人名+年N歲） | `光緒元年乙亥希濤年十歲` / `中華民國元年希濤年四十七歲` | 袁觀瀾先生手編年譜 |
| **2. 無稱謂（直接附年齡，無先生/公/府君）** | | |
| 直接年齡 | `十九年甲戌七嵗` | 萬清軒先生年譜 |
| 年N嵗 | `二十三年癸卯，年二十六` | 方柏堂變體 |

| 出生條目 | `仁宗睿皇帝嘉慶十三年戊辰八月二十四日先生生` | 通用 |
| 出生日期（無生字） | `明萬厯四十六年戊午十一月二十一日辰時` | 施愚山先生年譜 |

| **7. 干支+直接年齡（裸干支緊接年齡，無年號）** | | |

| **8. 現代學者整理本（現代學者已編好年份標題，不重新匹配正文）** | | |
| 現代學者整理本 A（年號在前） | `#### 嘉慶十八年 癸酉 1813年 一岁`（已有標題，檢查是否全＋統一格式） | 劉熙載年譜 |
| 現代學者整理本 B（公元在前） | `#### 一九二三年（民國十二年癸亥）二十三歲` | 王欣夫先生編年事輯稿 |

> 註：表中 8 組族類中，「出生條目」（第 3 組）是各族通用的子類，只用於年號播種，並非獨立格式族；故 L1 格式預分類只偵測 7 個獨立格式族（見「演算法」一節）。

## 公元年標註

處理完成後，會在所有含年號+年序的標題干支後自動標註公元年：

```
### 嘉慶十一年丙寅（1806年）十月一日戌時
### 道光三十年庚戌（1850年）四十五歲
### 光緒元年乙亥（1875年），年七十歳
```

換算方式：`公元年 = 年號元年公元 + 年序 - 1`（如 咸豐八年 = 1851 + 8 - 1 = 1858）。

年號與元年的對應表存在 `REIGN_START_YEARS` 配置（含異體字 萬厯/萬曆、光緖/光緒 等），涵蓋宋代、元代、明代（含南明）、清代、清末宣統、民國百餘個年號。年號不在表中、或標題只有干支無年序（如「丙申，公四十一嵗」）時，保持原樣不標註。

**公元年號標題本身也會標註阿拉伯數字**：`### 公元一八七三年（1873年），同治十二年，岁次癸酉，一岁`（依中文數字逐位轉換，如 一八七三=1873、一九五零=1950）。

## 演算法

### 預處理

年譜文字在切分前經過三層清理：

- **年號字形正規化** — `光緖→光緒`、`萬厯/萬厤→萬曆`、`永厯→永曆`、`康熈(U+7188)→康熙` 等異體字統一為標準字形，避免因字形變體導致年號匹配遺漏。
- **OCR 錯誤修正** — `先元年→先生年`、`十年九→十九`、`宏治→弘治` 等常見古籍 OCR 誤讀自動替換。
- **HTML 註解剝離** — 移除分頁標記 `<!-- 第X頁 -->` 等干擾。
- **跨行合併** — 年份與年齡因排版斷行分處兩行時（`康熙十六年\n公七歲`），自動接合為一條完整年份條目。

### L1 格式預分類

`classify_format()` 在匹配前先掃描全文，偵測六種格式族，只啟動相關的正則子集，從源頭降低誤配：

| 格式族 | 偵測條件 | 適用年譜 |
|--------|---------|---------|
| `person` | 含「先生/公/府君〔年〕N嵗」 | 方柏堂、張清恪、府君風格 |
| `no_person` | 含「N年干支…N嵗」（無稱謂） | 萬清軒、澄懷主人、顧亭林風格 |
| `ad` | 含「公元N年」 | 項蘭生等近現代年譜 |
| `bare` | ≥5 個行首/句末「N年干支」（無年齡） | 紫陽（朱熹）等無年齡純年份年譜 |
| `bare_gz` | ≥5 個行首裸干支，後不接干支 | 鄭端簡公等行首干支逐年標記年譜 |
| `modern` | ≥2 行可解析的已有年份標題 | 劉熙載、王欣夫等現代學者整理本 |

出生 pattern 在所有格式族下均啟用，以確保年號播種。`modern` 格式（現代學者整理本）不經正則匹配，只走「統一標題格式＋完整性檢查」流程。

### 年份匹配

正則匹配按優先級從嚴到寬依次嘗試，共分為 **有稱謂、無稱謂、無年齡、公元年、行首裸干支** 五大類。

**有稱謂（含傳主名前綴）：**
- `birth` — 出生：`[前綴]N年[干支]...先生生/公生/府君生`，中間不跨句號
- `entry_sb` — 有干支：`[前綴]N年干支 + [最多120字] + 先生[年]N嵗`，中間不跨句號
- `entry_no_sb` — 無干支：`[前綴]年號N年...先生N嵗`，年號前綴必需
- `entry_sb_direct` — 行首干支：`干支， + [最多30字] + 先生N嵗`，標點必需

**無稱謂：**
- `birth_no_person` — 出生：`N年[干支]...生於`，中間禁止冒號（防止「治亂生於人心」誤判），可跨一句號
- `entry_sb_no_person` — 直接年齡：`N年[，]干支[，][年]N嵗`，年齡後綴必需

**無年齡：**
- `entry_bare` — `(前綴)?(年號)?N年干支`，限行首/句末，干支必備，放 alternation 末尾避免搶佔有年齡條目

**近現代公元年：**
- `ad_entry` — `公元NNNN年，[年號N年，][岁次干支，]N岁`，年齡後綴必需

**行首裸干支（bare_gz 格式）：**
- `entry_bare_gz` — 行首裸干支：`庚申、` / `己亥春入京` / `丁卯。公九歲`
- `entry_bare_ls` — 行首完整年標：`隆慶元年丁卯`（僅卷首/年號更替處）
- `entry_bare_se_yuan` — 句末元年：`元年干支`（僅年號更替處）

三種 bare_gz pattern 匹配後不直接生成標題，而是由 `_expand_bare_gz_heading` 依「干支 60 年週期 ＋ 當前年號」推算年號年序與公元年，補全為 `### 嘉靖十八年己亥（1539年）`。

### 年號補全與追蹤

掃描過程中維護一個當前年號狀態。遇到無年號前綴的條目（如 `二年乙酉，先生二十七歲`），自動補上當前年號變為 `順治二年乙酉，先生二十七歲`。年號切換時自動更新當前年號。行首裸干支格式則依干支週期推算年序，不直接補年號。

### 後處理鏈

匹配完成後依次執行：

1. **合併斷行** — 將因排版斷開的行重新接合，檢測跨年邊界防止誤合
2. **嵌入式年份二次掃描** — 合併後段落中隱藏的密集年份（如 `八年戊子五歲。九年己丑六歲`）拆出為獨立標題
3. **月份/季節分段** — 每一年內按 `春/夏/秋/冬` 及月份拆分，以 `**春正月**` 標記；季節複合詞（秋闈、冬至）不切分
4. **公元年標註** — 對所有含年號+年序的標題，在干支後插入 `（YYYY年）`，換算公式 `公元年 = 年號元年 + 年序 - 1`

### 自我進化

每次處理後自動掃描文本，發現不在已知列表中的年號、皇帝前綴、字形變體，存入 `learnings.json`。同一年號出現 ≥2 次且置信度 ≥0.4 後自動應用到後續處理。手動修正可通過 `--record "錯" "對" [來源]` 回饋到學習系統：干支形近字（單字替換，如 順治乙亥→己亥）累積為 OCR 候選規則（帶上下文＋來源），`--status` 列出出現 ≥2 次的候選供人工複核後手動升級 `_OCR_FIXES`（**不自動晉升**，年序推論錯誤屬校勘不沉澱為字形規則）；年號/前綴/字形類修正自動標記相關學習為無效。`--prune` 命令批量清理已無效的學習記錄。

### L2 三錨點一致性檢查

`verify_anchors()` 對每條標題交叉驗證三個錨點：
- **年號年→公元** vs **干支→公元** vs **年齡→公元**；出生年以「干支+年齡」餘類多數決推定（`_consensus_birth_year`：一致率 ≥60% 且樣本 ≥5），年號年序多數決落於該餘類內時互相佐證，否則以文本年號 span 解出唯一絕對年——對「年號年序系統性誤刻」（許敬菴尾部錯一年、尙友堂掉十）魯棒
- 相鄰標題的年齡序列是否逐年遞增

不一致者輸出「⚠ 可疑標題」清單供人工複核。`--check <已整理.md>` 可對既有整理檔唯讀複查。

### CBDB 生卒年核驗與年號誤配自動修正

`--cbdb <傳主名>` 以中國歷代人物傳記資料庫（CBDB）的生卒年為錨，自動從卷首提取傳主名（或提供別稱映射），帶本地快取，斷網時回退。

- **出生年核驗**：比對三錨點多數決推定與 CBDB（差 ≤1 年為虛歲/源文本之別）；年譜最大年份 < CBDB 卒年−2 時標註「自訂/自編年譜止於卒前 N 年」。
- **年號誤配自動修正**：對 L2 標記的年號年序誤標，以「虛歲→公元」推定真年、干支佐證，依 `REIGN_END_YEARS` 年號終年表判定正確年號年序（如崇禎止於 1644，故 1645 切換為順治二年）。`--fix` 一鍵改寫標題年號年序＋公元註記，干支/年齡保留。**CBDB 缺席**（查無／斷網／無生卒日期）時，`--fix` 回退到內部「干支+年齡」共識出生年（`_consensus_birth_year`），冷門傳主仍可自動修（陳紫峰「正德三年戊寅→十三年戊寅」實例）。

### L2 衝突 LLM 仲裁（nianpu_arbitrate.py）

當 `--check` 標出的衝突 `--fix` 無法判定（無年齡／干支歧義）時，`nianpu_arbitrate.py` 仿標點 chunk→LLM→merge→verify 模式：

1. `--request <已整理.md>`：收集三錨點衝突＋鄰近標題上下文＋推定出生年 → `<名>_仲裁請求.md`
2. LLM 讀請求逐條判定（每行：`{標題} → {修正後標題}` 或 `→ 不改`）
3. `--apply <已整理.md> <仲裁結果.md>`：保守套用——只動年號年序（含公元註記），干支/年齡/正文/前綴一律保留；修正後年號年須與干支自洽（`(ad−4)%60 == 干支索引`），不滿足的判定直接拒絕；套用後復驗三錨點並報剩餘衝突。

### 語義槽位模型（--slots）

`slot_model.py` 將「每年譜改正則」抽象為「填槽位表」。LLM 以 schema + few-shot 範例讀取新年譜開頭，輸出槽位 JSON（紀年形式、年齡前綴、後綴、字形變體等），工具直接套用覆蓋格式分類與傳主名前綴，使新格式不需改正則（v3.29 補 `gz_age` 槽位，李恕谷式「干支+直接年齡」小書亦可用 `--slots` 表達）。`--slots <slots.json>` 輸入。

## 常見問題

**Q: 輸出亂碼？**

A: 確認輸入文件為 UTF-8 編碼。若非 UTF-8，腳本會自動嘗試 GBK/Big5。

**Q: 年份未被切分？**

A: 可能原因：
- 年份與年齡相隔超過 120 字（中間有超長註文）
- 缺少干支且無年號前綴
- 使用的年號不在支援列表中（自我進化系統可自動發現）
- OCR 錯誤導致年份模式無法匹配（如「先元年」→工具已內建修正）

**Q: 某個年份被誤切？**

A: 註文中的年份+年齡組合（如「按武夷先生卒於丁亥，年七十八」）因不含干支且「年七十八」格式不匹配 `先生N歲`，一般不會誤切。若仍有誤匹配，可調整 `entry_sb` 的 120 字限制。

**Q: 光緖和光緒有什麼區別？**

A: 兩者是同一年號的不同字形（緖=緒的異體），工具會自動將 `光緖` 正規化為 `光緒`。

**Q: 首年正文開頭漏了「生於」/「生于」/「生」等字？**

A: 這是把出生日期併入標題（`### 嘉慶十一年丙寅十月一日戌時`）時常見的誤刪。標題只該「借用」日期顯示，正文的出生句（`{名}生於{地}`）必須原樣保留。整理首年後，檢查正文首句是否仍以「{名}生於/生于/生/誕」開頭——若正文直接以地點（如「平望鎭東溪湖第時…」）或家屬年齡開頭，即為漏刪，應對照原稿補回人名+動詞。

## 年譜擴展利用：人際網絡數據提取

> **整理好的年譜不只做 RAG／文本分析，還能再往下游「提取為結構化數據」——人際／社交網絡。**
>
> 由另一獨立 skill **[nianpu-social-network](../nianpu-social-network/SKILL.md)** 提供：把已整理的年譜按年通讀，用 **hyperextract（`he parse`，LLM + 自訂模板）** 抽出「誰和誰、是什麼關係、哪一年、原文依據」，整理成**統一 persons / relations / dataset_meta 三個 TSV**（含 class_axis／relation_class 分類、aliases、evidence、year），為**多人譜合併、跨人物分析、知識圖譜**做底座。
>
> **首個落地案例：〔袁觀瀾（袁希濤）先生手編年譜及續〕**——約 200 餘位人物、300 餘條關係；產出三份結構化 TSV 之外，另附同構知識圖譜（`data.json`＋nodes／edges.csv）與一份按關係分類的人際網絡《整理稿》。
>
> **延展建議**（詳見「常見問題／後續」）：本工具改造為「整理 → 標點 → 歸檔 → **再餵給 nianpu-social-network 提取數據**」的完整管線；兩 skill 共用同一份定稿 `.md`，年份標題＋有標點的正文，正是提取出可靠 year／evidence 的前置條件。
