# 年譜整理工具 / nianpu-processor

一鍵處理原始古籍刻本 OCR 後的中國年譜文本、或從識典古籍等下載的年譜文本，自動按年份切分、補全年號、整理段落。支援明清兩代及南明年號，並已擴展至公元年號/民國紀年的近現代年譜（民國以後），具備自我進化能力。

本工具旨在為中國歷史人物、思想史、哲學史、學術史研究搭建數字基礎文本——將結構混亂的年譜原始文本轉化為結構清晰、可由 AI Agent 自動識讀的 Markdown 格式，便於後續搭建 RAG 知識庫、進行大規模文本分析與哲學史、思想史、史學研究。

> **📋 [年譜整理工具測試報告（v3.15）](docs/年譜整理工具測試報告.md)**

>
> **📋 [整理前後 RAG 檢索效果對比報告](docs/整理前後RAG效果對比報告.md)**
> 以 3 部年譜（文貞公／殷譜經／王欣夫）× 4 個年齡（25/35/45/55），用 BM25 模擬 RAG 檢索，量化「整理後按年分塊」對答案精確度（縮小 62 倍）、噪音（減少 151 倍）與受限預算召回率（34%→87%）的提升。

**重跑測試流程**（更新報告數據用）：

```bash
# 以年譜資料目錄為參數，產出各年譜標題數/覆蓋率/遺漏/可疑/生卒年
python tools/nianpu_coverage.py <年譜資料目錄>        # JSON 寫入 docs/nianpu_report_data.json
python nianpu_processor.py --check <已整理.md> --cbdb <傳主名>   # 單部複查＋CBDB 核驗
python tools/nianpu_rag_compare.py <年譜資料目錄> [年齡清單...]  # RAG 檢索效果對比（整理前 vs 整理後）
```

## 功能

- **年份標題化** — 將 `八年己巳，先生年五十二` 轉為 `### 八年己巳，先生年五十二`
- **公元年標註** — 在標題干支後自動標註公元年：`### 嘉慶十一年丙寅（1806年）`，依 `REIGN_START_YEARS` 年號元年換算
- **公元年號/民國格式** — 近現代年譜：`公元一八七三年，同治十二年，岁次癸酉，一岁` → `### 公元一八七三年（1873年），同治十二年，岁次癸酉，一岁`（涵蓋光緒/宣統/民國，支援 廿/卅）
- **年號補全** — 自動追蹤當前年號，對無年號的條目標題補上年號
- **OCR 容錯** — 自動修正常見 OCR 錯誤（`先元年`→`先生年`、`十年九歲`→`十九歲` 等）
- **年號字形正規化** — `光緖`→`光緒`、`萬厯`/`萬厤`→`萬曆`、`永厯`→`永曆`
- **月份/季節分段** — 每一年內按 `春/夏/秋/冬` 拆分，以 `**春正月**` 標記
- **嵌入式年份拆分** — 合併後段落中二次掃描隱藏的密集年份（如 `八年戊子五歲。九年己丑六歲`），支援行首出現、一行多處匹配，並自動沿用前一年號補全
- **跨年邊界檢測** — 合併斷行時檢測年份邊界，防止不同年份誤合
- **自我進化 v3** — 每次處理後自動發現新年號、新字形、新前綴，含置信度評分和假陽性過濾
- **從修正中學習** — 手動修正後的結果會反饋到學習系統，自動標記無效學習
- **審查清理** — `--prune` 命令批量移除已被標記為無效的學習
- **檢查報告** — 處理完成後自動比對原始文本，報告遺漏年份、年齡空缺、年號切換
- **RAG 檢索效果對比** — `tools/nianpu_rag_compare.py` 用 BM25 模擬 RAG，對比「整理前 vs 整理後」年譜的檢索效果（答案塊品質 hit／噪音／長度、Recall@K、受限預算召回率）；自動偵測 整理前（`_完整`／原始）與 整理後（`_已整理`）配對、出生年與標題層級，輸出逐書報告與匯總表
- **現代學者年譜支援** — 已有年份標題（`#### 嘉慶十八年 癸酉 1813年 一岁`／`#### 一九二三年（民國十二年癸亥）二十三歲`）的現代學者編年譜，不重新匹配正文，只「檢查年份標題是否全」＋統一格式：解析既有標題 → 推定出生年 → 交叉驗證 年號年/干支/公元年/年齡 四錨點 → 列出缺年清單（供人工確認該年是否無事可記）
- **傳主名前綴自動偵測** — 近代年譜常直接以傳主名為年齡前綴（如袁觀瀾年譜「光緒元年乙亥希濤年十歲」），非傳統「先生/公/府君」。自動偵測「緊接 (年號)N年干支 之後」的反覆前綴並納入該譜稱謂集合，使有稱謂 pattern 得以套用、民國無干支條目（`中華民國元年希濤年四十七歲`）得以切分；僅統計緊接干支之後、且非全由年齡數字構成的前綴，避免誤檢無稱謂格式的「二十/三十/卒年/夫人」等
- **民國無干支年條目** — `中華民國元年希濤年四十七歲`（有稱謂年齡錨點、無干支）經 `entry_no_sb` 切分並標註（1912年）；`中華民國六年\n\n希濤五十二歲` 跨空行年份+年齡自動合併；`中華民國十六年丁卯`（無年齡、有干支）經 `entry_bare` 切分
- **行首裸干支年標（v3.21）** — 明代年譜全譜以行首「干支」逐年標記（`庚申、`／`己亥春入京`／`丁卯。公九歲`／`戊申在尚寶`），年號僅於卷首與年號更替處出現。自動偵測（行首裸干支 ≥5 觸發）後，以「干支週期＋當前年號」推算年號年序與公元年，補全為 `### 年號N年干支（公元年）` 標題；`entry_bare` 在該格式下收緊為「僅行首完整年標＋句末元年」（排除正文散文干支日期如「永樂十九年辛丑」「二十六年甲申」誤切）。干支 OCR 變體 丙→内（内申/内午）、戍→戌（壬戍）自動修正；槽位 `year_style: ganzhi_only` 亦驅動此能力（`--slots` 與自動檢測結果一致）
- **語義槽位模型（v1 原型，`slot_model.py`＋`--slots`）** — 把「每年譜改正則」抽象為「填槽位表」：年份條目由 紀年／年齡／事件 三類錨點構成，`slot_model.llm_prompt()` 以 schema＋few-shot（已處理年譜的槽位實例）引導 LLM 讀新年譜開頭→輸出槽位 JSON，`nianpu_processor --slots <json>` 直接套用（覆蓋格式分類、傳主名前綴、行首裸干支 year_style=ganzhi_only，並套用 ocr_variants），新格式不需改正則；`slot_model.arbitrate_prompt()` 為 L2 三錨點衝突生成 LLM 仲裁 prompt（出口端）
- **年號字形正規化擴充＋出生誤判修復（v3.22）** — `_REIGN_NORMALIZATIONS` 新增 `康熈（U+7188）→康熙`（原僅康煕 U+714F，李二曲年譜全譜「康熈N年」因字形變體未被識別而全數遺漏，正規化後康熙年標題 100% 覆蓋）；`birth_no_person` 中間段禁冒號（：/：），修復「…有感嘆曰：治亂生於人心」的「生於」（義為「起於」）被誤當出生條目、標題吞噬正文的 bug

## 快速開始

本工具設計為**可供各種 AI 智能體（Claude Code、Cursor、Copilot 等）直接用自然語言調用**——智能體讀取本文件與 `SKILL.md` 後，會自動解析意圖並執行底層 `nianpu_processor.py`，無需手動拼寫參數。例如：

> 「整理這個年譜文件」→ 自動切分年份標題、補全年號、標註公元年
> 「把《黃黎洲先生年譜》整理好」→ 指定檔案處理
> 「核驗傳主生卒年並修正年號誤標」→ 觸發 `--cbdb`／`--fix`
> 「檢查已整理檔的可疑標題」→ 觸發 `--check`

亦可在終端直接執行腳本：

```bash
# 處理年譜文件，輸出為「原檔名_已整理.md」
python nianpu_processor.py 涇舟老人洪琴西先生年譜_完整.md

# 指定輸出檔名
python nianpu_processor.py input.md output.md

# 語義槽位配置（v1 原型）：LLM 依新年譜開頭推得槽位 JSON，直接套用，不需改正則
python nianpu_processor.py input.md output.md --slots slots.json

# 查看自我進化學習狀態
python nianpu_processor.py --status

# 清理已標記為無效的學習
python nianpu_processor.py --prune
```

## 公元年標註

處理完成後，會在所有含年號+年序的標題干支後自動標註公元年：

```
### 嘉慶十一年丙寅（1806年）十月一日戌時
### 道光三十年庚戌（1850年）四十五歲
### 光緒元年乙亥（1875年），年七十歳
```

換算方式：`公元年 = 年號元年公元 + 年序 - 1`（如 咸豐八年 = 1851 + 8 - 1 = 1858）。

年號與元年的對應表存在 `REIGN_START_YEARS` 配置（含異體字 萬厯/萬曆、光緖/光緒 等），涵蓋宋代、元代、明代（含南明）、清代、清末宣統、民國百餘個年號。年號不在表中、或標題只有干支無年序（如「丙申，公四十一嵗」）時，保持原樣不標註。

**公元年號標題本身也會標註阿拉伯數字**：`### 公元一八七三年（1873年），同治十二年，岁次癸酉，一岁`（依中文數字逐位轉換，如 一八七三=1873、一九五零=1950）。

## 處理流程

```
讀取檔案
  → 年號字形正規化（光緖→光緒）
  → OCR 錯誤修正（先元年→先生年）
  → 合併跨行年份+年齡（沈端恪格式支援）
  → 查找年份標記（前綴 + N年干支 + 先生N歲 / 直接N歲 / 澄懷主人無稱謂格式）
  → 插入 ### 標題
  → 追蹤並補全年號
  → 合併斷行（含跨年邊界檢測）
  → 嵌入式年份二次掃描（密集年份拆分）
  → 按月份/季節分段（**春正月**）
  → 輸出
  → 自動檢查報告
  → 自我進化學習
```


## 演算法

### 預處理

年譜文字在切分前經過三層清理：

- **年號字形正規化** — `光緖→光緒`、`萬厯/萬厤→萬曆`、`永厯→永曆`、`康熈(U+7188)→康熙` 等異體字統一為標準字形，避免因字形變體導致年號匹配遺漏。
- **OCR 錯誤修正** — `先元年→先生年`、`十年九→十九`、`宏治→弘治` 等常見古籍 OCR 誤讀自動替換。
- **HTML 註解剝離** — 移除分頁標記 `<!-- 第X頁 -->` 等干擾。
- **跨行合併** — 年份與年齡因排版斷行分處兩行時（`康熙十六年\n公七歲`），自動接合為一條完整年份條目。

### L1 格式預分類

`classify_format()` 在匹配前先掃描全文，偵測六種格式族，只啟動相關的正則子集，從源頭降低誤配：

| 格式族 | 偵測條件 | 適用年譜 |
|--------|---------|---------|
| `person` | 含「先生/公/府君〔年〕N嵗」 | 方柏堂、張清恪、府君風格 |
| `no_person` | 含「N年干支…N嵗」（無稱謂） | 萬清軒、澄懷主人、顧亭林風格 |
| `ad` | 含「公元N年」 | 項蘭生等近現代年譜 |
| `bare` | ≥5 個行首/句末「N年干支」（無年齡） | 紫陽（朱熹）等無年齡純年份年譜 |
| `bare_gz` | ≥5 個行首裸干支，後不接干支 | 鄭端簡公等行首干支逐年標記年譜 |
| `modern` | ≥2 行可解析的已有年份標題 | 劉熙載、王欣夫等現代學者年譜 |

出生 pattern 在所有格式族下均啟用，以確保年號播種。`modern` 格式不經正則匹配，直接走「統一標題格式＋完整性檢查」流程。

### 年份匹配

正則匹配按優先級從嚴到寬依次嘗試，共分為 **有稱謂、無稱謂、無年齡、公元年、行首裸干支** 五大類。

**有稱謂（含傳主名前綴）：**
- `birth` — 出生：`[前綴]N年[干支]...先生生/公生/府君生`，中間不跨句號
- `entry_sb` — 有干支：`[前綴]N年干支 + [最多120字] + 先生[年]N嵗`，中間不跨句號
- `entry_no_sb` — 無干支：`[前綴]年號N年...先生N嵗`，年號前綴必需
- `entry_sb_direct` — 行首干支：`干支， + [最多30字] + 先生N嵗`，標點必需

**無稱謂：**
- `birth_no_person` — 出生：`N年[干支]...生於`，中間禁止冒號（防止「治亂生於人心」誤判），可跨一句號
- `entry_sb_no_person` — 直接年齡：`N年[，]干支[，][年]N嵗`，年齡後綴必需

**無年齡：**
- `entry_bare` — `(前綴)?(年號)?N年干支`，限行首/句末，干支必備，放 alternation 末尾避免搶佔有年齡條目

**近現代公元年：**
- `ad_entry` — `公元NNNN年，[年號N年，][岁次干支，]N岁`，年齡後綴必需

**行首裸干支（bare_gz 格式）：**
- `entry_bare_gz` — 行首裸干支：`庚申、` / `己亥春入京` / `丁卯。公九歲`
- `entry_bare_ls` — 行首完整年標：`隆慶元年丁卯`（僅卷首/年號更替處）
- `entry_bare_se_yuan` — 句末元年：`元年干支`（僅年號更替處）

三種 bare_gz pattern 匹配後不直接生成標題，而是由 `_expand_bare_gz_heading` 依「干支 60 年週期 ＋ 當前年號」推算年號年序與公元年，補全為 `### 嘉靖十八年己亥（1539年）`。

### 年號補全與追蹤

掃描過程中維護一個當前年號狀態。遇到無年號前綴的條目（如 `二年乙酉，先生二十七歲`），自動補上當前年號變為 `順治二年乙酉，先生二十七歲`。年號切換時自動更新當前年號。行首裸干支格式則依干支週期推算年序，不直接補年號。

### 後處理鏈

匹配完成後依次執行：

1. **合併斷行** — 將因排版斷開的行重新接合，檢測跨年邊界防止誤合
2. **嵌入式年份二次掃描** — 合併後段落中隱藏的密集年份（如 `八年戊子五歲。九年己丑六歲`）拆出為獨立標題
3. **月份/季節分段** — 每一年內按 `春/夏/秋/冬` 及月份拆分，以 `**春正月**` 標記；季節複合詞（秋闈、冬至）不切分
4. **公元年標註** — 對所有含年號+年序的標題，在干支後插入 `（YYYY年）`，換算公式 `公元年 = 年號元年 + 年序 - 1`

### 自我進化

每次處理後自動掃描文本，發現不在已知列表中的年號、皇帝前綴、字形變體，存入 `learnings.json`。同一年號出現 ≥2 次且置信度 ≥0.4 後自動應用到後續處理。手動修正的結果可通過 `_record_correction()` 回饋到學習系統，自動標記相關學習為無效。`--prune` 命令批量清理已無效的學習記錄。

### L2 三錨點一致性檢查

`verify_anchors()` 對每條標題交叉驗證三個錨點：
- **年號年→公元** vs **干支→公元** vs **年齡→公元**（出生年由「年號年−年齡+1」多數決推定）
- 相鄰標題的年齡序列是否逐年遞增

不一致者輸出「⚠ 可疑標題」清單供人工複核。`--check <已整理.md>` 可對既有整理檔唯讀複查。

### CBDB 生卒年核驗與年號誤配自動修正

`--cbdb <傳主名>` 以中國歷代人物傳記資料庫（CBDB）的生卒年為錨，自動從卷首提取傳主名（或提供別稱映射），帶本地快取，斷網時回退。

- **出生年核驗**：比對三錨點多數決推定與 CBDB（差 ≤1 年為虛歲/源文本之別）；年譜最大年份 < CBDB 卒年−2 時標註「自訂/自編年譜止於卒前 N 年」。
- **年號誤配自動修正**：對 L2 標記的年號年序誤標，以「虛歲→公元」推定真年、干支佐證，依 `REIGN_END_YEARS` 年號終年表判定正確年號年序（如崇禎止於 1644，故 1645 切換為順治二年）。`--fix` 一鍵改寫標題年號年序＋公元註記，干支/年齡保留。

### 語義槽位模型（--slots）

`slot_model.py` 將「每年譜改正則」抽象為「填槽位表」。LLM 以 schema + few-shot 範例讀取新年譜開頭，輸出槽位 JSON（紀年形式、年齡前綴、後綴、字形變體等），工具直接套用覆蓋格式分類與傳主名前綴，使新格式不需改正則。同時為 L2 三錨點衝突生成 LLM 仲裁 prompt。`--slots <slots.json>` 輸入。

## 常見問題

**Q: 輸出亂碼？**

A: 確認輸入文件為 UTF-8 編碼。若非 UTF-8，腳本會自動嘗試 GBK/Big5。

**Q: 年份未被切分？**

A: 可能原因：
- 年份與年齡相隔超過 120 字（中間有超長註文）
- 缺少干支且無年號前綴
- 使用的年號不在支援列表中（自我進化系統可自動發現）
- OCR 錯誤導致年份模式無法匹配（如「先元年」→工具已內建修正）

**Q: 某個年份被誤切？**

A: 註文中的年份+年齡組合（如「按武夷先生卒於丁亥，年七十八」）因不含干支且「年七十八」格式不匹配 `先生N歲`，一般不會誤切。若仍有誤匹配，可調整 `entry_sb` 的 120 字限制。

**Q: 光緖和光緒有什麼區別？**

A: 兩者是同一年號的不同字形（緖=緒的異體），工具會自動將 `光緖` 正規化為 `光緒`。

**Q: 首年正文開頭漏了「生於」/「生于」/「生」等字？**

A: 這是把出生日期併入標題（`### 嘉慶十一年丙寅十月一日戌時`）時常見的誤刪。標題只該「借用」日期顯示，正文的出生句（`{名}生於{地}`）必須原樣保留。整理首年後，檢查正文首句是否仍以「{名}生於/生于/生/誕」開頭——若正文直接以地點（如「平望鎭東溪湖第時…」）或家屬年齡開頭，即為漏刪，應對照原稿補回人名+動詞。
