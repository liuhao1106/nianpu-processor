# 回歸測試（tools/regression.py）

## 為什麼要有它

**弱點③**：改動 `nianpu_processor.py` 後的回歸測試長期靠手工重跑舊案例，v3.23 起「6 案例差異=0」式量化回退記錄斷檔——歷史成績既不可自證，改碼也無自動防線。

本套件把「已成功處理」的成績變成**可複現的黃金測試**，改動後一條命令驗證不退化。

## 檔案結構

| 檔案 | 角色 |
|------|------|
| `tools/regression.py` | 回歸測試主程式（stdlib 零依賴） |
| `tools/testdata/*_source.md` | 各案例的源文本（自包含，換機可跑） |
| `tools/testdata/*_golden.md` | 各案例的黃金輸出（當年歸檔的已整理檔） |
| `tools/testdata/regression_manifest.json` | 每案例：源/黃金路徑、格式、模式、槽位 |
| `tools/testdata/regression_baseline.json` | 基線：`--selfcheck` 從黃金輸出實測（不手寫、防漂移） |

## 雙參照比對

1. **行為快照**（baseline.metrics）＝上次審核通過的管線輸出指標——回歸測試的對象。改碼後行為若變（標題數/覆蓋率/出生年/可疑數），`--run` 報 FAIL。
2. **黃金輸出**（baseline.golden）＝當年歸檔文件的指標——驗證「歷史成績是否可復現」。差異一律列 **WARN**（人工修正已寫回源檔的案例 ≠ 純自動管線能力，誠實分開），不擋 PASS。

## 模式分級

| 模式 | 斷言 | 適用 |
|------|------|------|
| `exact` | 標題數、推定出生年、可疑數（不得增）、覆蓋率（容差 0.5%）全比對；標題數須與黃金輸出一致 | 源可直接復現黃金（文貞公/陳紫峰/警石府君/殷譜經/王欣夫） |
| `metric` | 標題數不降、覆蓋率不低於基線-1.0%、不崩潰；黃金差異列 WARN | 人工修正較多、或已知缺口（方柏堂/萬清軒/紫陽文公/重刻鄭端簡） |
| `smoke` | 只驗證跑通不炸 | 快速冒煙 |

## 用法

```bash
python tools/regression.py --selfcheck      # 建立/重建基線（從黃金輸出實測）
python tools/regression.py --run            # 重跑九案例 vs 基線 → PASS/FAIL 表＋回歸行
python tools/regression.py --run --full     # 另掃 E: 識典數據 全庫（24+ 案例）
python tools/regression.py --run --update   # 人工審核本次結果合理後，刷新基線
python tools/regression.py --smoke          # 快速冒煙
```

`--run` 通過時自動輸出 changelog 用回歸行：

```
回歸：文貞公年譜 75/方柏堂先生譜系略 40/… 標題數不變（9 案例差異=0）
```

直接粘進更新日誌即可——解決「不再記錄量化回退」的問題。

## 改動腳本後的標準流程

1. 改 `nianpu_processor.py`／配置
2. `python tools/regression.py --run`
3. 全部 PASS → 收工，把回歸行貼進 changelog
4. 有 FAIL → 先修，別帶回退發版
5. 功能**確有改進**（新格式/新修正）→ `--run --update` 刷新基線後再收工

## 已知缺口（首建基線即暴露，均列 metric 哨兵案例）

| 案例 | 現況 | 黃金 | 問題 |
|------|------|------|------|
| 重刻鄭端簡公年譜 | 145 標題 | 72 | 〔〕注文（`癸亥、〔弘治十六年，公五歲。〕`）被當獨立標題展開，與行首裸干支雙重匹配；含「正德十七年壬午（1522年）」錯題（正德止於十六年） |
| 紫陽文公先生年譜 | 79 標題 | 75 | 無年齡純年份格式誤切正文，多出不可能年份：慶元十年（慶元止 6 年）、紹熙三十七年/五十二/五十六（紹熙止 5 年） |

修復後應把模式升回 `exact`，使標題數與黃金輸出一致。

## 邊界與限制

- **回歸標的＝基礎規則集**：直接呼叫 `process_nianpu`，不走 `main()` 的 `apply_learnings()`——learnings.json 是經驗累積，非回歸對象，故結果可跨機複現。
- **標點／仲裁不在範圍**：`nianpu_biaodian.py`／`nianpu_arbitrate.py` 屬 LLM-in-loop 步驟，由各自的 `--verify` 字符保全校驗兜底。
- **指標式比對（非全文 diff）**：抓「標題數/覆蓋率/出生年/可疑數」層的退化；不抓「改了輸出但指標不變」的 bug。這是刻意取捨——大量黃金輸出含人工修正，全文 diff 必然假陽性。
- 部分案例黃金差異屬**人工修正已寫回源檔**（方柏堂 41 vs 40、萬清軒 80 vs 82），非工具退化，WARN 僅供人工判斷。
